## EXP-001：测试数据生成与验证

**日期：** 2026-10-27（Asia/Shanghai）  
**状态：** 已完成  
**目的：** 固化后续算子测试所需输入和 golden，避免重复生成与计算。

### 实施内容

- 编写 [generate_cases.py](script/generate_cases.py)。
- 生成 40 个 case，各自保存 `x1`、`x2`、最终 FP32 `golden` 和配置。
- 基于量化后的实际 FP16/BF16 输入，用 FP64 完成点积、Max 和 Sum，最终转 FP32。
- 沿 M/N 分块计算 golden，不保存完整相似度矩阵。
- 同形状、同 dtype 的基础布局用例使用相同逻辑输入。
- 保存 SHA256、文件大小、生成耗时等信息；支持跳过已完成 case 和校验缓存。

### 执行命令

从仓库根目录运行：

```bash
/opt/venv/bin/python implement/script/generate_cases.py
/opt/venv/bin/python implement/script/generate_cases.py --verify
```

另执行一次性独立验证，检查全部输入格式，并对前 32 个 case 使用完整 CPU FP64 矩阵乘核对 golden；该一次性验证程序未单独保存为脚本，结果已保存到验证报告。

## EXP-003：small 分支 SIMD / WMMA 初版与路径对比

**日期：** 2026-10-27（Asia/Shanghai）  
**状态：** 初版实现与指定范围验证完成；自动选择和其他切分路径待实施  
**目的：** 在相同任务范围下比较 SIMD 与矩阵指令，观察 M/N 形状、B、K、dtype 和布局的影响。

### 实施内容

- 一个 block/wave32 对应一个 B，在同一 kernel 内完成全部点积、Max 和 Sum，无 workspace、计数器或输出清零。
- Matrix：rocWMMA 16×16×16，支持 FP16/BF16、四布局与尾块，FP32 累加；通过 LDS 整理输入和归约累加器结果。
- SIMD：同一条点积由 lanesK 个 lane 协作，其他 lane 并行 N；支持 lanesK=1/2/4/8/16/32。
- 显式 computePath；Auto 暂返回 NotImplemented。未实施沿 M/N 多 block、groupB>1、双缓冲或跨 block 切 K。
- 增加参数检查、C ABI、CMake 静态/共享库及 Python 实验入口。
- 执行计划记录实际 base/group 范围，未把未知配置伪装成调优结果。

### 构建与接口检查

Release / gfx1100，开启 -Wall -Wextra -Werror，CMake 静态库与共享库构建通过。规划接口的无效输入、未实现配置和失败不改计划检查通过；一次性主机检查程序位于 /tmp/bmms_api_check.cpp，不属于持久化测试套件。

FP16、BF16 反汇编均发现 v_wmma_f32_16x16x16 指令。最终源码指纹保存在 [source_fingerprints.json](hip/results/source_fingerprints.json)。

### 正确性

- 使用持久化 case 1–26、28–31，共 30 个，每个检查 Matrix 和 SIMD lanesK=1/4/8/16/32，共 180 项。
- 暂定判定：abs_error <= 1e-4 + 1e-4*abs(golden)，全部通过；尚未固化赛题最终误差解释。
- 最大绝对误差 0.0205688477，最大相对误差 2.15356104e-05；这两个最大值不一定来自同一配置。
- 每种配置额外重复运行 3 次，结果相等；两个 stream 共享只读输入、使用独立输出检查通过。
- 并未对全部 40 个 case 执行 HIP 算子验收，极限规模不属于当前 small 分支性能扫描范围。

### 性能扫描

- 基础 105 个点：B={1,8,64}，M/N={(1,1),(1,16),(1,128),(8,16),(16,16),(17,17),(32,64)}，K={32,40,128,1024,8192}，FP16、F/F。
- 交叉 64 个点：B={1,64}，M/N={(1,16),(16,16)}，K={32,8192}，两 dtype、四布局。
- 每点六种配置，扫描时额外核对独立 FP64 参考结果。
- HIP event 包围 HIP Graph，预热后测三批取中位数；单次校准低于 100 μs 时批内至少 64 次，其余至少 3 次。CSV 保存实际重复数与三批原始样本。
- 不包含分配、输入生成、golden、数据搬运和编译，包含 graph 调度开销。
- 第一轮探索开头与正确性验证短暂重叠，已标记 exploratory_*，不用于正式结论；正式版本已串行重测。

### 单 kernel 核对

rocprofv3 smoke 对 Matrix 和 SIMD 各调用一次。日志共有两个 fused_small kernel 与四个外部 memcpy 触发的运行时 copy kernel。按 HIP API correlation 核对：两个融合 kernel 均对应独立 hipLaunchKernel，四个 copy kernel 对应调用范围外的 memcpy，不将整份日志行数作为算子启动次数。

### 初步结论与限制

- M=N=1 的样例明显偏向 SIMD；M=N=16 的样例偏向 Matrix，不能用 B×M×N 单一乘积决定路径。
- K 改变耗时差距与 SIMD 最佳 lanesK，布局也会影响结果，需依据逐点数据而非固定猜测分派。
- Matrix 仅有一个初版配置，SIMD 比较了五种 lane 配置；这是实现级对比，不是两类硬件指令的最终性能上限。
- 尚未实现其他切分路径，因此还不能确定 small 与沿 M/N 切分的分界，也未启用 Auto。
- 后续优先检查 Matrix 输入整理/行归约成本、SIMD 加载与 K 分工，再在接近的路径边界补点。

### 测量口径

每个 case 精确执行 10 次未计时拆分调用，随后捕获 100 次调用的 HIP Graph；没有 replay 预热，只有一次计时 replay。GPU event 测总 device elapsed，再除以 100，得到算术平均 μs。不是 CPU wall time，不是中位数，不使用自适应重复次数。包括必要中间显存流量和设备/graph 调度。

```bash

```

### 检查与结果

- 40 个 case 均测量完成，计时 CSV 恰有 40 行，编号连续。
- 逐行核对 warmups=10、iterations=100、耗时有限且大于零，以及 mean_us=total_device_ms×1000/100，全部通过。
- 预热后及测量结束后均与保存 golden 按 abs<=1e-4+1e-4*abs(golden) 核对，全部通过。
- 计时不包含参考结果验证；没有新增相似度矩阵数据文件。
- 不复测融合 kernel；旧融合耗时采用不同协议，不能直接作为严格可比的加速比。

## EXP-006：SplitB 分支实施与持久化 case 测试

**日期：** 2026-10-27（Asia/Shanghai）  
**状态：** 已完成实现、正确性验证及所选case正式计时  
**目的：** 实现 fused_split_b，在不跨block切M/N的前提下，提高任务内部协作和输入复用。

### 实施内容

- 新增 KernelFamily::SplitB，Small入口和计算保持兼容；新增 wavesPerBatch 配置及 bmms_split_b C ABI。
- 一个block负责groupB个batch，各batch由多个wave分担M tile；每个wave遍历完整N/K，最后block内固定顺序合并部分和。
- base固定16×16×16；groupBaseM=16*wavesPerBatch，groupBaseN=16/32/64；相邻N tile在K循环内复用A fragment。
- 完整且对齐的tile直接全局rocWMMA加载；尾块和不对齐leading dimension采用每wave独占LDS打包。
- wave内同步含内存栅栏，最终一次block barrier；无全局scratch、计数器、atomicAdd或初始化kernel。
- 独立构建/tmp/bmms-splitb-build，保留此前small测量二进制。严格编译和静态/共享库构建通过。

### 测试选择与结果

- case1–32 ×12配置，共384项正确性检查通过；每项额外重复3次结果相等。
- 覆盖两dtype、四布局、M/N/K尾块、groupB尾部、无工作wave、全负、零batch、大K抵消和长M归约。
- 双stream独立输出检查通过；Small Matrix/SIMD入口在case1/9/25/28/30回归通过。
- case37–40在groupB=1/wavesPerBatch=4/groupBaseN=64下单次正确性通过，pilot为142–317ms。
- case33–36为B=1、M/N/K同时极大，不作为SplitB合适测试，不运行。
- 主要性能case9–16 ×12配置，共96项，10次预热、100次device算术平均。计时公式和加速比逐行检查通过。
- 大B极限case不展开多配置搜索；根据pilot确定一次代表配置的完整测量仍可控，补做四个case的10/100正式平均。
- profiler smoke：一个split-B kernel；另3个外部memcpy运行时copy kernel，已通过HIP API关联编号区分。
- 参数校验测试通过：groupB/wave非法组合、非支持groupBaseN、未实现SIMD路径、空指针和篡改执行几何均不会误启动kernel。

case9–16的最快实测配置，比此前相同10/100协议的Small最快配置快约8.28–16.32倍，但仍慢于拆分基线。现有case中B=64只出现在M/N=8192极限形状，缺少大B且M/N适中的用例，不能据此泛化高B性能。
