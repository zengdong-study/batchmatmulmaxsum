# Split-M / Split-N 实验记录（MN-001）

**日期：** 2026-10-28（Asia/Shanghai）

**状态：** 两条路径已实现；最终版32-case正确性、并发隔离、正式计时及单kernel检查完成。未宣称全部40-case验收。

## 问题与实现

仅沿B分配任务时，B较小的问题无法提供足够独立block。本模块新增沿M/N分组的矩阵指令路径，并将最终汇总保留在同一次kernel内。提供独立C++/C ABI和共享库，不修改Small/Split-B实现。

- Split-M：每任务处理groupBaseM行和完整N/K，发布一个部分Sum；最后一个block按固定树形组织合并。
- Split-N：每任务处理groupBaseN列和全部M/K，发布M个局部Max；最后一个block先逐行合并Max，再Sum(M)。
- FP16/BF16、四种连续布局；完整K后才取Max，N尾块以负无穷屏蔽，M尾块不参与Sum。
- 两个独立N tile累加器复用当前A fragment；每个wave负责16行。加载函数是本轮开始时的稳定快照，未跟随其他模块的并行修改。

## 单kernel完成协议与工作区

每任务写入独占部分结果，经block barrier后以agent范围acq_rel原子计数发布。最后一个block中的每个收尾线程各自acquire读取完成计数，然后按固定索引读取部分结果并归约。写y后以release store复位计数器。没有跨block自旋、浮点atomicAdd或第二个归约kernel。

调用方首次使用工作区前，须按stream顺序H2D复制B个零uint32计数器；partial区无需初始化。后续同计划、同stream调用及HIP Graph replay由kernel内复位支持；并发调用必须使用独立工作区和输出。接口是否允许首次工作区初始化仍需与最终评测契约核对，本实现不宣称无需初始化。

## 正确性与生命周期验证

只加载已有case1–32，逐文件和manifest元数据/指纹核对；不生成输入或新的golden。M路径配置为(groupSize,waves)=(16,1)/(64,4)/(256,8)，N路径在这三组外增加(64,2)，共224项。

每项首次调用及额外3次重复均通过暂定混合误差标准；重复前将输出预置NaN，确认覆盖写；重复结果严格相等，每次调用后计数器均归零。最大绝对误差0.0206298828125，最大相对误差2.1599514330447008e-05。

另在两条路径上验证双stream、独立输出/工作区、每stream连续20次调用。正式计时后的额外不计时graph replay检查工作区复用。主机测试覆盖非法维度/配置、失败规划保留输出、篡改grid/groups/workspace、空指针、工作区不足及对齐错误，均在启动GPU前拒绝。

结果见[最终正确性](results/final_validation/summary.json)、[并发](results/final_validation/concurrency.json)和[综合核对](results/verification.json)。case33–40未纳入本轮验证；不能由32个case推断极限形状通过。

## 正式性能与对照

每项恰好10次未计时预热，捕获100次调用，仅一次计时replay，GPU event总device耗时/100为算术平均。输入搬运、dtype转换、分配、工作区初始化、graph捕获及验证均在计时外。额外验证replay不进入性能样本。

同一GPU（gfx1100，UUID和版本指纹保存在各identity/environment文件）上另测32项FP32 bmm→amax(N)→sum(M)拆分基线。所有192项融合正式计时（初版64+最终默认64+细粒度64）和32项基线均通过golden检查。旧Small/Split-B结果不用于替代这组同机对照。

## 单kernel核对

rocprofv3 smoke分别调用M、N一次；按HIP API correlation验证恰好2个fused_split_mn kernel，各对应一次hipLaunchKernel。其他dispatch均关联计时外memcpy，不能算成算子内额外启动。最终库指纹与正确性/计时一致，见[核对报告](results/final_profile/verification.json)。

## 剩余瓶颈与后续范围

- 稳定快照加载器仍有奇数leading dimension退回多次半精度加载的成本；K大时加载等待、寄存器整理和WMMA依赖主导，尚未应用双缓冲或进一步合并加载。
- 两个N tile复用A，但未显式跨M tile复用B；增大group并不会自动产生这种复用。
- B小且M/N tile都少时，沿M/N切分仍不足以占满GPU；更多任务还可能增加尾块、部分结果及收尾开销。
- Split-N的B×ceil(N/groupSize)×M部分Max存储及合并成本随M增长；M大/N小时应比较Split-M或专用路径。
- 未覆盖case33–40，未启用Auto或跨block split-K；首次计数器初始化的最终评测契约未确认。以上是明确边界，不把未测项视为完成。
