# 16项严格精度修复：诊断与实施顺序

日期：2026-10-29。本计划已按顺序实施至严格精度候选完成：新入口40/40同时满足绝对/相对<1e-4，原16项数值问题已修复；性能代表未通过，暂不替换S6快版。保留S6冻结入口及全部性能证据作为回退。见[实施报告](results/precision_20261029_entry/严格精度修复报告.md)。

## 目标与事实

在赛题档位/组合解释未进一步明确前，保守按最终FP32输出的绝对误差<1e-4、相对误差<1e-4分别验收；不能用现有混合检查替代。参考仍为原输入实际存储值的FP64点积→Max→Sum→最终FP32，不改变输入、种子或golden。

这些只是误差分布，不是根因结论。17–24同dtype四布局输出完全一致，提示数值累加路径值得优先排查；33–36当前输出均低于golden，也不能仅凭符号认定是哪层导致。

37–40的输出约2690，FP32相邻值间距为0.000244140625，大于1e-4。因此这组严格绝对门槛实际要求最终FP32与golden逐位一致。其他组也记录ULP距离，不只报小数误差。

## 第一步：建立分层误差账本

先只用原代表case17、21、33、34、37、38；涉及布局搬运变化后再扩展其余原case。诊断与正式计时分开。

1. 保存每batch实际输出、golden、绝对/相对误差、FP32 ULP距离及有符号误差。
2. 诊断当前点积所得行Max，在计时外用FP64求Sum并最终转FP32：若这一步已不达标，说明仅改最后Sum不够。
3. 再以FP64完整点积得到的行Max喂入当前Sum组织，量化最后Sum自身的误差。它只是诊断，不是最终算子或性能结果。
4. 对split-K路径分别观察每份C、合并后的C、每行Max及最终Sum；比较FP32合并与FP64合并，不先改所有层。
5. 核对近似Max的列索引、FP64赢家及第一/第二名间隔。并列时允许索引不同，但最终数值必须正确；索引一致也不能证明点积精度足够。

大矩阵诊断按原输入的N分块流过FP64参考，保留行级统计；不为诊断生成新case，不把全量FP64 C长期落盘。区分点积舍入、Max选择变化与Sum舍入，避免把三个误差简单相加当严格分解。

## 第二步：先做成本最低的最终Sum修复

只将最终收尾的线程局部累加、wave/block树归约和scratch改为FP64，最终只转一次FP32。行Max部分结果暂仍为FP32，其他数据流不动。

- 优先检查37–40，再检查长K组；预期是减少大量行相加的舍入，但不承诺一次解决全部16项。
- 不能只把最终float结果cast成double，那无法恢复已经丢失的精度。
- 小型Sum不需要全GEMM改成FP64；也不改变发布/计数器复位协议。
- 保留FP32旧Sum作同轮对照。若误差仍超标，就明确进入点积修复，不靠更换求和顺序碰运气。

## 第三步：提高点积和split-K合并精度

先处理17–24的小输出矩阵，建立可验证方法后扩展到33–36。

1. 单独将8路K部分和合并改为FP64，判断合并舍入是否关键。部分和内部误差不会因此消失。
2. 比较少量固定K段长，例如128/256：每段WMMA累加器归零，段间用FP64或补偿累加合并，再进入Max。记录寄存器、LDS、同步和指令成本，不做无限参数扫描。
3. 若短段WMMA本身仍不够，比较明确的FP32 FMA补偿累加或FP64点积诊断，定位需要补偿的层级。FP64全GEMM只作精度上界/成本对照，不能默认它能保持速度。
4. 精度路径中的Max必须比较完成全部K后的值；如需保留FP64点积精度，行Max与部分结果区也应保持FP64，不能过早转回float。

最终策略只按形状/dtype/布局元数据固定，不能读取case编号、golden或输入分布决定是否启用高精度。

## 第四步：必要时研究有可靠性保障的Max候选重算

这是备选，不是首选实现。Max只需要真正赢家的高精度值，可能比提高所有C元素精度便宜；但只重算近似argmax或固定top-2会漏掉被舍入排到后面的真实赢家，不能作为正确方案。

可靠路线须先为近似点积建立适用于实际WMMA语义的误差界。对每个候选构造区间[L_n,U_n]，令L*=max(L_n)，所有U_n≥L*的列都必须高精度重算；不能靠经验间隔剔除列。无法证明界时，只能做诊断，不能放行。

可在每个N tile内完成候选确认/重算，再发布高精度tile行Max，沿用单kernel最后CTA收尾。必须包含候选筛选、重算、额外加载和收尾成本；并列很多时可能退化到全量精确计算，不能假设数据总有明显赢家。

## 验证、性能与停止条件

- 每次只改一个主要精度环节，新结果目录保存源码/库/环境/数据身份，旧S6不覆盖。
- 先代表项严格精度、ULP、重复、NaN输出覆盖、输入不变、工作区边界和独立stream；失败立即保存，不扫性能。
- 精度改动涉及的16项全部严格通过后，重新回归原40case，确保30的抵消和25的全负输入没有退化。
- 每调用仍须1kernel；禁止外部精确预计算、原生多kernel回退、错误输出修正常数或依赖旧输入的缓存。
- 性能保持完整10预热/100次device均值，同轮比较冻结S6及FP32拆分链；小余量项5轮交错，保留每轮，不取最小值。
- 最终记录“严格精度通过且逐项快于基线”的交集，不能用精度通过但慢的结果或快但不准的结果宣布解决。

建议实施顺序：误差账本 → FP64最终Sum → FP64 split-K合并 → 短段WMMA加高精度段间合并 → 必要时补偿点积/有证明的候选重算。

首次workspace初始化契约是独立问题，本计划不会因为精度修复而自动认定其获准。

## 本轮执行后的调整

FP64最终Sum和split-K合并均不足，短段与补偿分解解决长K，有界FP64候选重算解决大B短K。严格精度和单kernel均已过40项，但性能预算及两项完整10/100失败；下一轮先拆分初算/候选/重算/收尾成本，再决定tile与协作方式。放大N tile和缩窄最终行Max两个试验没有收益，已保留，不再把它们当默认优化方向。
